# 仪表投屏 v2.2.2 发行说明

> 车机端 APK：`com.xiaopeng.vdcast`（「仪表投屏」），Android 12 / 2400×1200。
> 这一版新增**全屏投屏**，并修好全屏取景与「框选」对不上的问题。
> 左/右 2/3 栏的执行逻辑与 v2.2.1 一致。

## 一、新增：全屏投屏

面板上多了一个「全屏投屏」勾选框。勾上后：

- 不再强制把目标应用摆进 2/3 栏，按**窗口真实大小**取画面；
- 应用已经是全屏（`mFrame` 铺满 2400×1200）→ 整块画面投出去；
- 应用还在 2/3 栏 → 只投这一栏，**不会出现左边黑条、右边被切**；
- 运行中把应用拖到全屏 / 拖回 2/3，5 秒内自动重新取景；
- 停止时按投屏前的状态还原：全屏进全屏出，2/3 栏进同栏出。

车机的窗口管理器只按 2/3 栏摆放窗口，`am task resize` 改不了窗口帧，
所以「真全屏」仍需用户手动拖一次（或应用自己请求全屏）；勾选框不改变这一点，
只是让取景老实按窗口实际大小来。

## 二、修复：框选看到的 ≠ 实际投出的

旧版全屏模式完全忽略用户框选：发送端按整块窗口帧取景，再按仪表区比例自动裁，
而框选页画的是整块虚拟屏截图上的框 —— 两边自然对不上。

现在全屏模式用 **「窗口帧 ∩ 框选框」** 当裁切源：

- 框里是什么，仪表上就是什么；
- 框选≈整块屏时退回按窗口帧取；
- 框选与窗口不相交（<160px）时也退回窗口帧，避免全黑。

另外 `winFrame()` 改为取同包**面积最大**的窗口帧，避免拿到启动页/悬浮窗。

## 三、工具：installapk.sh

本 ROM 拒绝 `adb install`（`isPlatSigned:false`），只能走图形安装器。
`tools/installapk.sh` 这版改为：

- `uiautomator dump` 判断当前页（「要更新此应用吗」走 RIGHT+ENTER，否则 ENTER）；
- 按键序列写成车机侧脚本、`setsid` 一次跑完（PC 分步发 keyevent 一掉线对话框就消失）；
- 读不到旧 `lastUpdateTime` 时重试、仍读不到就报错，避免“假成功”；
- 轮询 22 秒确认真的装上。

```bash
bash tools/installapk.sh adbprobe/AdbProbe.apk com.xiaopeng.vdcast vdcast.apk
```

## 四、实车验证（8295 / 2400×1200）

| 项目 | 结果 |
|---|---|
| 全屏窗口 + 勾全屏 | `full mode ... window=Rect(0, 0 - 2400, 1200)`；仪表 1920×720 铺满 |
| 2/3 窗口 + 勾全屏 | `full mode ... window=Rect(960, 0 - 2400, 1080) crop=1440x1080`；无黑边、无缺右 |
| 框选一致性 | 框 `751,64,1501×1009` → `args crop=Rect(751, 64 - 2252, 1073)`，仪表即该区域 |
| 停止还原 | 全屏进全屏出；2/3 栏进同栏出 |
| 帧率 | 车机 59fps、仪表 35fps（827×556 区域） |

## 五、已知限制

- 真全屏依赖用户把窗口拖到全屏（车机 WM 限制），面板无法代劳。
- 1920×720 虚拟屏实测：百度地图、高德地图都不自适应，窗口仍按 2400×1200 排版，
  搬进 720p 虚拟屏会被裁掉一截 —— 所以**没有**做 1920×720 预设（会丢信息）。
- 运行中换栏/拖全屏依赖 5 秒轮询，最长 5 秒旧画面。
- 保活（后台 30 分钟不被杀）仍未验证（与 v2.2 同）。
