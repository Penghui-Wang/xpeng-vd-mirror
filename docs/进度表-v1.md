## 0. 使用规则（先读这四条）

1. **一条需求一行，ID 不改**。新增需求只能追加新 ID（如 `ADB-13`），不许改旧 ID 的语义，否则历史记录对不上。
2. **状态只有 6 种**，且必须能落到证据上：

   | 状态 | 含义 | 准入条件 |
   |---|---|---|
   | 未开始 | 还没动 | — |
   | 进行中 | 有人在做 | 写清在做的人/轮次 |
   | 待验收 | 代码或资产已交，但没按 DoD 在车机上跑过 | 必须挂「待验项」 |
   | 已验收 | 按 DoD 跑过且有证据 | 必须有截图/日志/md5 路径 |
   | 暂缓 | 已决策推迟，不阻断当前轮 | 写清为什么缓、什么条件下重启 |
   | 取消 | 已决策不做 | 写清替代方案 |

3. **没有证据 = 没做完**。「我改好了」不算，`build OK` 只算构建通过，不算验收。
4. **每轮开发收尾必做三件事**：① 回填本表状态；② 在 §3 追加一条变更记录；③ 在 `CHANGELOG-改造记录.md` 追加本批「改了什么 / 怎么验的 / 没做什么」。

### 2026-11-05 18:36（B5 根因：Adb 单连接并发吞包 —— stop 卡死不是 restore 的锅）

- **根因**：`Adb.readAll()` 只认自己那条流的包，别的流（含对方的 `CLSE`）直接丢弃；两条命令并发时，先读完的那条把另一条的收尾包吃掉，后者永远等不到结束 → 读到超时。`execRc` 超时又会 `close()` 整条连接，于是后面的 kill -9 / 二次 stop 全报「未连接」，整条收尾中断（17:53 那两次把接收端留在仪表上）。
- **触发条件**：3 秒补测（旧实现：裸线程直接 `a.exec`）与 `stop` 撞在同一条连接上。两次历史卡死都发生在「就绪后约 2.5s 发 stop」，而补测在就绪后 3s 触发，正好落进 `[1/4]` 的 4.3s 窗口。
- **四组对照（同一台车、同一份 stop）**：① PC 直连 `killvds stop` 8/8 正常；② 走 APK 每秒采样 10 轮 0 复现；③ 走 APK 加压 30 轮 0 复现；④ **把补测改回裸线程（故障注入）→ 第 1 轮就复现，stop 15976ms**；⑤ 保持④并给 Adb 加 `synchronized` → **8/8 正常**；⑥ 最终包（锁 + 补测走 worker）4/4 正常。
- **修复**：`Adb.exec/execRc/push/pull/connect/close` 全部 `synchronized`（根因），补测改走 `worker`（去掉触发条件）。
- **证据**：`docs/materials/b5/repro/`（`hang_r1.log` 复现日志、`stress_stop.sh` 复现脚本）；分析见 `docs/B5-启动链分解-v1.md` §7。
- **口径更正**：之前把这条记成「`killvds stop` 里 `app_process --restore` 偶发卡死」——**不对**，restore 本身没问题（④⑤ 两次里它都在 0.3s 内打出 `nothing to do`）。

## 6. 约束分两档（13:20 修正：原来写的「红线」有两条过严）

### 6.1 硬约束（真的别试）

1. **不并行两个宿主连 adbd**。已随旧包卸载自然满足，别再把旧包装回来。
2. **不往 git 提交 `*.der` / `adbkey*`**。`.gitignore` 已有 `*.der`、`*.pem`、`*.p12`，提交前仍要 `git status` 复看一眼——私钥进公开仓库是不可逆事故。
3. **安装只走图形安装器**。`adb install` / `pm install` 在这个 ROM 上永远失败，别把这当成环境故障去排查。

### 6.2 注意项（可以做，但要按顺序）

4. **改包名 / 卸载重装**：会生成新 key，需要重新授权一次（首次连接时完成）。若卡住 → 开发者工具里「无线 ADB」关开一次复位。**升级优先用覆盖安装**，纯粹为了省掉这次授权。
5. **首次连接别连点**：一次授权请求只走一条路；`ADB-12` 已保证一进程只提交一次公钥，但人为反复点「连接」仍可能叠出多个 socket，没必要。
6. **保活当成「未验证」**：UX-14 暂缓，不要写进交付说明里当卖点。
